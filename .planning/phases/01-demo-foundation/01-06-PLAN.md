<task type="auto">
  <name>Task 1: Create GitHub Actions workflow</name>
  <files>
    .github/workflows/deploy.yml
  </files>
  <action>
    Create .github/workflows/deploy.yml:

    ```yaml
    name: Deploy to GitHub Pages

    on:
      push:
        branches: [main]
      pull_request:
        branches: [main]

    permissions:
      contents: read
      pages: write
      id-token: write

    concurrency:
      group: "pages"
      cancel-in-progress: true

    jobs:
      build:
        runs-on: ubuntu-latest
        steps:
          - name: Checkout
            uses: actions/checkout@v4

          - name: Setup Node
            uses: actions/setup-node@v4
            with:
              node-version: '20'
              cache: 'npm'

          - name: Install dependencies
            run: npm ci

          - name: Lint
            run: npm run lint

          - name: Type check
            run: npx tsc --noEmit

          - name: Build
            run: npm run build

          - name: Upload artifact
            uses: actions/upload-pages-artifact@v3
            with:
              path: ./dist

      deploy:
        needs: build
        if: github.ref == 'refs/heads/main' && github.event_name == 'push'
        runs-on: ubuntu-latest
        environment:
          name: github-pages
          url: ${{ steps.deployment.outputs.page_url }}
        steps:
          - name: Deploy to GitHub Pages
            id: deployment
            uses: actions/deploy-pages@v4
    ```

    Note: Using the newer GitHub Pages actions (actions/upload-pages-artifact, actions/deploy-pages) which are the recommended approach for 2024+, rather than peaceiris/actions-gh-pages.

    Create .github directory if it doesn't exist.

  </action>

    Option 1 (Recommended for Phase 1): Use hash routing
    - Update src/main.tsx to use createHashRouter instead of createBrowserRouter
    - Routes become /#/chat, /#/settings, etc.
    - Simpler, no additional files needed

    Since Phase 1 only has chat view (no complex routing yet), we can use hash routing:

    ```typescript

    import { createHashRouter, RouterProvider } from 'react-router-dom';

    const router = createHashRouter([
      {
        path: '/',
        element: <App />,
      },
      // Future routes will be added here
    ]);
    ```

    If not using React Router yet (minimal Phase 1):
    - Skip this step for now
    - App.tsx renders everything without routing
    - Add routing in Phase 2 when multi-channel views are needed

    Create public/404.html as fallback for future:
    ```html
    <!DOCTYPE html>
    <html>
      <head>
        <meta charset="utf-8">
        <title>Robo Assistant</title>
        <script>
          // Redirect to index.html with the path as a query parameter
          // React Router will pick it up and navigate correctly
          sessionStorage.redirect = location.href;
        </script>
        <meta http-equiv="refresh" content="0;URL='/'">
      </head>
      <body>
        Redirecting...
      </body>
    </html>
    ```

    And corresponding script in index.html to handle the redirect:
    ```html
    <script>
      (function(){
        var redirect = sessionStorage.redirect;
        delete sessionStorage.redirect;
        if (redirect && redirect != location.href) {
          history.replaceState(null, null, redirect);
        }
      })();
    </script>
    ```
